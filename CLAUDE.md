## Running locally

> **Next.js warning**: This project uses Next.js 16, which has breaking changes vs. earlier versions. Before writing any Next.js code, read the relevant guide in `frontend/node_modules/next/dist/docs/`.

### Frontend (Next.js)

```bash
cd frontend
cp .env.local.example .env.local   # set NEXT_PUBLIC_BACKEND_URL, NEXT_PUBLIC_IMAGEKIT_URL
npm install
npm run dev        # starts on :3000
npm run build      # production build
npm run lint       # ESLint
```

Runs on port 3000 by default — run the backend on a different port (e.g. `PORT=3001`) if running both locally.

### Backend

**Prerequisites:** Node.js 20+, MongoDB Atlas M0 (free), Gemini API key, Cloudinary free account.

```bash
cd backend
cp .env.example .env      # fill in all values — see table below
npm install
npm start                 # prestart copies templates, then starts on :3000
```

Dev mode (restarts on file changes):
```bash
npm run dev               # runs copyTemplates.js then node --watch server.js
```

Verify: `curl http://localhost:3000/healthz` → `{"status":"ok"}`

> **Critical gotcha — template sync**: `frontend/public/rate-card.html` (the Puppeteer template) is copied into `backend/templates/` only at server start via `scripts/copyTemplates.js`. Edits to `rate-card.html` are **invisible to Puppeteer** until the backend restarts or you run `node scripts/copyTemplates.js` manually.

### Tests

```bash
cd backend
npm test              # runs all Jest tests in __tests__/
npm run test:watch    # watch mode
```

`email` (unique, lowercase) · `passwordHash` · `name` · `bio` (max 80 chars) · `portfolioUrl` · `portraitUrl` · `photoLocked` (bool — set after portrait changed once via `/api/user/photo`) · `createdAt` / `updatedAt`

`userId` (ref User, nullable) · `callType` (resume_parse|linkedin_parse|score) · `inputTokens` · `outputTokens` · `thinkingTokens` · `totalTokens` · `model` · `createdAt`

## Backend architecture

### LLM service (`services/llm.js`)

Gemini is the primary provider; Groq (`llama-3.3-70b-versatile`) is the fallback. Fallback logic:

- **Transient error** (503 overload, 429 per-minute): fall back to Groq for this request only; Gemini not blocked
- **Daily quota exhausted** (429 with `per_day`/`daily` in message): block Gemini in-memory until midnight UTC; all subsequent requests go to Groq
- **Both fail**: retry Gemini once; if still failing, throw `{status:503}` with a user-friendly message
- **Unrelated error** (e.g. 400): rethrow immediately, no fallback

State (`geminiBlockedUntil`) is in-memory and resets on server restart.

### Card generation pipeline

```
POST /api/card/generate
  → buildCardData(user, card)          cardData.js
  → renderCard(cardData)               puppeteer.js
      ├── inject window.CARD_DATA into rate-card.html (before </head>)
      ├── write to templates/_render/<uuid>.html
      ├── page.goto /_internal/template/_render/<uuid>.html
      ├── viewport: 1053×1470 px, deviceScaleFactor: 2  → 2106×2940 PNG
      └── screenshot #artboard element
  → uploadCardImage(buffer, userId)    cloudinary.js
      └── public_id: card_{userId}  (overwrites on re-generate)
  → save amCode + imageUrl + linkedinUrl to DB
```

### Score generation pipeline

```
POST /api/score/generate
  → scoreProfile(rawProfile)           scoring.js
      ├── complete(SYSTEM, prompt, { json: true })   llm.js → Gemini (Groq fallback)
      │     Returns: rate, replaceability, chessPiece, employmentStatus,
      │              delta, educationOrg, workOrg, bioRewrite
      ├── clamp rate + replaceability to [13, 99]
      └── getOrgLogo(eduName) + getOrgLogo(workName) in parallel
              └── Brandfetch → Clearbit HEAD https://logo.clearbit.com/{slug}.com
                  → monogram SVG fallback if 404 / timeout
  → save all fields to Card document
```

### Auth flow (LinkedIn OAuth)

```
1. GET /api/auth/linkedin?intent=new
   → generates CSRF nonce (in-memory, 10-min TTL)
   → redirects to LinkedIn OIDC with state=base64(intent+nonce)

2. GET /api/auth/linkedin/callback  (LinkedIn redirects here)
   → validates state nonce
   → exchangeCode → access_token
   → getUserInfo → { email, name, picture }
   → upserts User in DB
   → uploadLinkedInPortrait to Cloudinary with e_upscale + quality:auto:best
   → stores full session payload in oauthSessions (2-min TTL, one-time)
   → redirects to FRONTEND_ORIGIN?oauth=<session_code>

3. GET /api/auth/linkedin/exchange?code=<session_code>  (frontend calls immediately)
   → consumes session code (deleted on first use)
   → returns { token, isNew, hasCard, name, photo, photoLocked, cardId, imageUrl, amCode }
```

### Puppeteer internals

- Singleton browser launched at server start (`initPuppeteer()` in `server.js`)
- Per-render: write temp HTML to `templates/_render/<uuid>.html`, navigate to it via `/_internal/template` static route, screenshot `#artboard`, then `page.close()` + delete temp file
- Page is closed immediately after screenshot — important for memory-constrained hosting
- Font loading awaited via `document.fonts.ready` before screenshot

### Cloudinary storage layout

| Folder | public_id | Content |
|---|---|---|
| `rate-cards/` | `card_{userId}` | Card PNG — overwritten on every re-generate |
| `portraits/` | `portrait_{userId}` | Portrait — overwritten on re-upload |

LinkedIn portraits are uploaded from URL then a transformation URL is returned (`e_upscale,q_auto:best`) — no local processing.

### Key utility functions

- `generateAmCode()` — 4 random uppercase letters + 4 random digits
- `replaceabilityToHourglass(n)` — maps score 13–99 to hourglass frame 1–10
- `statusToBlocks(status)` — maps employment status to 4 colored status chip configs
  - Index order: 0=retired (yellow), 1=intern (blue), 2=employed (green), 3=unemployed (red)

## Frontend architecture

### Next.js shell + legacy gallery scripts

The Next.js app is a thin shell: `GalleryPage.tsx` sets `window.*` globals then dynamically loads `scatter-gallery.js` and `ascii-logo.js` from `/js/` via script tags. The gallery and all modal logic live in those vanilla JS files; React is not involved in rendering the canvas or modal.

`lib/config.ts` exports:
- `BACKEND_URL`, `IMAGEKIT_URL` — from env vars
- `cdn(path)` / `cdnImage(path, tr)` — ImageKit URL builders (fall back to plain path if no `IMAGEKIT_URL`)
- `SCATTER_IMAGES` — explicit 50-image list (bypasses the HTTP probe loop in scatter-gallery.js; required when using a CDN origin)
- `CAROUSEL_IMAGES` — 3 hero carousel image URLs
- `SCATTER_PRIORITY` — set of priority image numbers that get `<link rel=preload>` treatment

### `scatter-gallery.js` — 3D gallery + lead modal

**Rendering**: Custom perspective projection (`FOCAL = 920`), camera `(x, y, zoom)`, depth-sorted draw loop. All rendering is on a `<canvas>` that fills the viewport. The lead modal is the only DOM overlay.

**Lead modal state machine:**
```
entry
  ├── NEW USER → LinkedIn OAuth redirect (intent=new)
  │     └── on ?oauth=CODE return → confirm → upload-cv → loading → card
  └── RETURNING? → existing-login
        ├── LinkedIn (intent=existing) → loading → card
        └── email + amCode → loading → card
```

- `confirm` mode: collects **bio** and **portfolio/LinkedIn URL** only (name and photo come from LinkedIn, not editable here)
- `card` mode: shows the generated card with action buttons and a LOG OUT button (two-click with 3 s auto-dismiss; clears `leadModal.token/cardId/imageUrl/amCode` then closes modal)
- `openCardModal(amCode)`: full-screen iframe overlay loading `/card/:amCode?embed=1`; iframe dimensions computed from `window.innerHeight` so the card fits without scrolling; share button copies the card URL to clipboard
- NEW USER entry always goes to LinkedIn OAuth (`intent=new`); the callback's `data.isNew` controls whether it routes to `confirm` (new) or straight to `card` (existing account)
- JWT stored in `leadModal.token`; never persisted to localStorage
- Touch: `passive: false` on all touch listeners; pinch-to-zoom range 0.22×–3.2×

### `backend/public/card-view.html` — shareable card page

- Fetches `GET /api/card/view/:code` on load
- Renders the Cloudinary PNG as `<img>` inside `.rr-card-wrap`; LinkedIn/portfolio URL is injected as `.rr-linkedin-overlay` (`<a>`) at runtime if present
- `?embed=1` hides the "CREATE YOUR OWN CARD" button — used when loaded in the modal iframe
- Card width: `min(clamp(220px, 42vw, 420px), calc((100vh - 180px) * 1053 / 1470))` — never requires scrolling
- **Hotspot tooltip system**: 14 `div.rr-card-hotspot` elements are percentage-positioned over the card image (z-index 5). JS wires `pointerenter/move/leave` on all `.rr-card-hotspot` elements to `#rrTooltip`. Hotspot CSS classes live in both `card-view.html` and `scatter-gallery.js` (the lead modal's inline card view) — **both files must be kept in sync** when adjusting hotspot positions or adding new ones.
  - Chips (top-right) use `right: %` positioning and are placed last in DOM to win z-order over the REPLACEABILITY hotspot in the overlap zone
  - Positions are % of the 1053×1470 artboard: rate (top-left), replaceability (top-right), portrait (centre), ticker (~64% top), logos (~68% top), portfolio link (~79% top), chess+identity+hourglass (86–99% top)

### `backend/public/leaderboard.html` — public leaderboard page

- Fetches `GET /api/leaderboard` on load; re-fetches when filter chips change
- Ranks cards by `rate − replaceability` (boardScore); shows top 50
- Filter bar: employment status chips + chess piece chips (all combinations, client-side query params)
- Optional `?amCode=` lookup: appends the user's own rank row below the table if they're outside the top 50
- Podium (top 3) rendered separately above the table with gold/silver/bronze styling

### `frontend/public/rate-card.html` — Puppeteer template

- 1053×1470 artboard; `transform: scale()` fits it to the container for browser preview
- `window.CARD_DATA` injected by Puppeteer before page load
- SVG `feConvolveMatrix` unsharp-mask applied to portrait `<img>` for sharpening
- Logo boxes show at most 3 org logos, left-to-right: educationOrg, workOrg
- CTA link (portfolio/LinkedIn) rendered as `<a class="cta-link">` at `top: 1180px`; URL priority: `user.portfolioUrl → card.ctaUrl → rawProfile.linkedinUrl → card.linkedinUrl`
- Status chips: 4 colored blocks (yellow/blue/green/red = retired/intern/employed/unemployed); active chip gets `opacity: 1` set via inline style in `renderStatusBlocks()` — do **not** rely on CSS class alone (Puppeteer may miss it)
- Hourglass frames: `../assets/hourglass/hourglass-{1..10}.png`
- Chess pieces: `../assets/chess/{piece}.png`

## Admin panel (`/admin`)

- Single HTML file, no framework
- Token: 8-hour JWT stored in `localStorage.adminToken`; auto-logout on any 401 response
- **Users tab** loads on login/refresh; **Cards tab** loads lazily on first click
- Refresh (F5) only re-fetches the Users tab — much faster than loading both
- Cards table: amCode links directly to `/card/:amCode` for quick card preview; LinkedIn URL shown as link

## Deploy (Railway + Vercel)

### Backend → Railway

Railway builds using the `Dockerfile` at the **repo root** (configured via `railway.json`). It:
1. Installs Chromium runtime dependencies
2. Runs `npm ci --omit=dev` inside the `backend/` directory
3. Copies `frontend/public/rate-card.html` and `frontend/public/assets/` into the image as the Puppeteer template source (`FRONTEND_PUBLIC_PATH=/app/frontend-public`)
4. Runs `npm start` → `prestart` copies templates → `node server.js` starts on `$PORT`

Do **not** set `PORT` or `BASE_URL` — Railway injects `PORT` automatically.

### Frontend → Vercel

Vercel root directory: `frontend`. Framework: Next.js (auto-detected). Required env vars: `NEXT_PUBLIC_BACKEND_URL`, `NEXT_PUBLIC_IMAGEKIT_URL`.

### Local Docker build

```bash
# from repo root (uses the root Dockerfile)
docker build -t raterace-backend .
docker run --env-file backend/.env -p 3000:3000 raterace-backend
```
